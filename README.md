# Сборка

Сайты, AI-ассистенты, веб-сервисы, интерактив и интеграции для агентств и бизнеса

Next.js 15, React 18, TypeScript, Three.js. Статические страницы и отдельный серверный Worker в одном Sites-проекте

## Разработка

Node.js 22.13+ для тестов с SQLite, npm

```bash
npm ci
npm run dev
npm run check:copy
npm run typecheck
npm run test:intake
npm run build
npm start
```

`dev` запускает Next.js с локальным сценарием заявки. `build` экспортирует сайт в `out/`, затем собирает `dist/client/` и `dist/server/index.js`. `start` проверяет готовый Worker и страницы на localhost:3104, база лимитов в этом превью временная. Без локального ключа чат продолжит работать через fallback

`npm run build:symbol` пересобирает резервные SVG из `src/site/motion/hero.json`. `node tools/preview/build.mjs` после сборки делает автономное превью `preview/index.html` без API

## AI-заявка

`POST /api/intake/next` вызывает GPT-5.4 mini через Responses API и Structured Outputs. Максимум 5 вопросов, до 4 вариантов. Контракт: `src/site/intake/contract.ts`, сервер: `server/`. При сбое модели интерфейс продолжает на локальном сценарии

Подготовка брифа работает через OpenAI. Доставка реализована в `/submit`, после настройки TELEGRAM_CHAT_ID заявки поступают боту в закрытую группу. Без получателя доступно копирование брифа. Свободный ввод контактов разрешен владельцем, формальная политика остается отдельной задачей. Подробности: `docs/telegram-delivery.md`

Ключ хранится только в серверных секретах Sites. Сборка удаляет его из окружения Next.js. Не добавлять ключи в `NEXT_PUBLIC_*`, Git, команды или браузер

| Переменная | Где | Назначение |
| --- | --- | --- |
| `CHATGPT_PLATFORM_API_KEY` | Серверный секрет Sites | Ключ OpenAI API |
| `NEXT_PUBLIC_INTAKE_API_URL` | Сборка | По умолчанию `/api/intake`, пустая строка для автономного mock |
| `NEXT_PUBLIC_INTAKE_DELIVERY_ENABLED` | Сборка | По умолчанию `true`, доступность получателя проверяется через `/config` |
| `TELEGRAM_BOT_TOKEN` | Сервер | Секрет бота |
| `TELEGRAM_CHAT_ID` | Сервер | ID закрытой группы заявок |
| `NEXT_PUBLIC_PRIVACY_URL` | Сборка | Ссылка на согласованную политику, пока пустая |
| `NEXT_PUBLIC_STUDIO_EMAIL` | Сборка | Только подтвержденный публичный email |
| `NEXT_PUBLIC_STUDIO_TELEGRAM` | Сборка | Только подтвержденный публичный username |

Сервер принимает JSON только с того же origin, проверяет длины и структуру. Полей контакта в `/next` нет; распознаваемые email, телефоны, Telegram и ссылки в свободном тексте маскируются перед вызовом модели. Контакты можно писать в любом сообщении, перед отправкой они показываются отдельно

D1 хранит только счетчики запросов: 30 на IP за 10 минут и общий предохранитель 1 000 обращений за 24 часа. IP заменяется HMAC с суточной ротацией. Истекшие записи удаляются небольшими порциями при запросах. Брифы и переписки в базе не сохраняются, в OpenAI задано `store: false`. Это не обещание нулевого хранения со стороны провайдера

Миграции генерируются `npm run db:generate`, лежат в `drizzle/` и применяются Sites при публикации. Уже опубликованные миграции не редактировать

## Проверки

`test:intake` проверяет серверный контракт, ошибки модели, скрытие внутренних полей, фильтрацию контактов, лимит вопросов, лимиты запросов с реальным SQLite, подтвержденную доставку, повторы и сбои Telegram. Он не вызывает платный API. Live-проверки делаются отдельно на синтетических задачах

Перед push: `check:copy`, `typecheck`, `test:intake`, `build` и проверка чата на desktop и 390 px

## Структура

- `BRAND.md` и `AGENTS.md`: актуальный бренд, TOV и правила изменений
- `src/app/`: главная, `/case`, `/report`, `/kit`
- `src/site/`: секции, чат, демо, 3D и навигация
- `src/components/`: компоненты действующей страницы `/kit`
- `server/`: серверная интеграция OpenAI и ограничения запросов
- `db/` и `drizzle/`: схема и миграции счетчиков
- `docs/`: контракт, принятые решения и дальнейшие задачи
- `tools/preview/`: автономное превью для согласования

Старый экспорт `project/`, архив `chats/`, одноразовый handoff и неиспользуемый `sections/Demos.tsx` удалены. При необходимости они доступны в истории Git. Рабочие страницы `/case`, `/report`, `/kit` и их компоненты сохранены
