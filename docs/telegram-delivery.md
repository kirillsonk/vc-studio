# Доставка заявок в Telegram

Обновлено 6 октября 2026

Владелец создал sborka_applications_bot, группу и серверный секрет TELEGRAM_BOT_TOKEN. Токен проверен через getMe, значение не извлекалось из Sites

## Настройка

- TELEGRAM_BOT_TOKEN: секрет бота, только сервер
- TELEGRAM_CHAT_ID: подтвержденная закрытая группа, только сервер
- INTAKE_ADMIN_SECRET: временный секрет для поиска группы через POST /api/admin/telegram, передается в Authorization: Bearer. После настройки удалить из Sites
- NEXT_PUBLIC_INTAKE_DELIVERY_ENABLED: разрешает доставку в интерфейсе, production-сборка по умолчанию true. GET /api/intake/config дополнительно проверяет наличие серверного получателя; без него отправка недоступна, но финальное поле контакта остается

## Поведение

Посетитель может добавить контакт в исходный текст или любой ответ. Явные email, телефоны и Telegram извлекаются из переписки, показываются перед отправкой, их можно заменить. Не требуется повторно писать известный контакт. Неоднозначные контакты без явных признаков могут потребовать уточнения

Контакт отправляется вместе с брифом только по явному нажатию «Все верно, отправить заявку». Под кнопкой указана цель обработки. Оператор и формальная политика все еще требуют данных владельца, их нельзя выдумывать или считать согласованными

Перед OpenAI распознаваемые контакты маскируются. В Telegram идет итог, исходная задача и ответы, чтобы сокращение AI не теряло детали. Не обещаем распознавание любых персональных данных или идеальную работу модели

## Надежность

POST /submit проверяет контракт, Origin, согласие и контакты. Лимит 5 попыток с проверенного IP за час; без него общий лимит 30 в час. Дополнительно действует общий предел 100 попыток в сутки. У заявки есть sessionId, хеш содержимого, статус и позиция следующего сообщения. Повтор после успеха возвращает тот же ID, конкурентная отправка блокируется

Telegram получает HTML с экранированным текстом, ссылки не разворачиваются. Длинные заявки разбиваются на части до 4096 символов. После явного отказа Telegram клиент может повторить отправку, продолжение начинается с первого неподтвержденного фрагмента

Если сеть оборвалась и ответ неизвестен, статус uncertain. Автоматического повтора нет: Telegram мог принять сообщение. Сайт не показывает успех и не обещает проверку доставки, черновик остается во вкладке. После предупреждения о дубле посетитель может явно подготовить новую отправку, повторно подтвердить контакты и согласие. Полная гарантия exactly-once при потере ответа Telegram отсутствует. Планировщик фоновых повторов не подключен

Node на Timeweb не использует отдельную БД и не сохраняет исходные данные заявки: в памяти остаются только хеш, статус, курсор и подтверждение доставки. Ограничения и защита от дублей действуют в пределах одного процесса и срока хранения технического состояния. После рестарта или нового деплоя оно сбрасывается, повтор может создать дубль. Результат сохраняется в самом Telegram

Адаптер D1 сохранен для прежнего размещения на Sites. Новые записи содержат техническое состояние без исходного текста заявки. Истекшие записи удаляются при следующей отправке. Логи не содержат текст заявок или токены

## Проверки

19 проверок сервера и модели демозаказа: входные контракты, маскирование контактов, история AI, лимиты, подтвержденная доставка, конкурентные повторы, частичная ошибка и возобновление, неопределенный сетевой результат, закрытый служебный маршрут

Адаптивы главной: 320, 390, 600, 768, 1062, 1280, 1440 px. Переполнение проверено по геометрии документа и основных блоков. Визуально проверены телефон, планшет и desktop: перенос примеров, свободный ввод, редактирование, известные контакты, график, цвет и объем бутылки, мобильное меню

## Формат заявки

На Sites короткий номер вида №001, на Timeweb стабильный короткий код заявки, в обоих случаях дата по Москве. Без постоянной БД сквозная последовательная нумерация не ведется. Жирные заголовки разделяют контакт, бриф, предварительный AI-разбор и оригинальный диалог. Вопросы и ответы подписаны ролями. HTML экранируется, подчеркивания в никах не меняются. Большой текст разбивается на части с тем же кодом и датой, URL страницы не добавляется

Перед отправкой клиент отдельно подтверждает контакт и выбирает канал для телефона. Это подтверждение правильности введенных данных, не проверка существования аккаунта
