# Аналитика и перенос на российский хостинг

## Метрика

Основной домен: sborkadigital.ru, выбран владельцем 6 октября 2026

Подключен счетчик 113480948. Публичный ID задан в src/site/analytics/metrika.ts, серверная переменная YANDEX_METRIKA_ID позволяет его переопределить. Значение 0 отключает счетчик. Ключи Яндекса не требуются. Локальные версии не запускают JavaScript счетчика

В интерфейсе Метрики нужно создать цели типа «Целевое событие» с точными идентификаторами:

| ID | Событие |
| --- | --- |
| intake_open | Переход к форме заявки |
| intake_start | Отправка первого описания задачи |
| brief_ready | Получен итоговый бриф |
| contact_review | Открыта карточка проверки контакта |
| lead_sent | Сервер подтвердил доставку заявки |
| demo_order | Оформлен условный заказ в демо |

Демо не отправляет ecommerce-выручку и не засчитывается как заявка. Номер, контакты и переписка не передаются в параметры событий. Вебвизор, карта кликов и отслеживание внешних ссылок включены по коду владельца. Яндекс Тег Менеджер отключен. Весь чат скрыт через ym-hide-content, поля ввода через ym-disable-keys, автоматическое отслеживание формы через ym-disable-submit. Карта кликов внутри чата отключена через ym-disable-clickmap. Ecommerce слушает dataLayer, но демонстрационный магазин не отправляет туда покупки. Просмотры передают только фиксированный путь страницы, без query и hash, referer только с origin. Автоматические цели и сбор содержимого форм в кабинете счетчика не включать

В кабинете счетчика указать sborkadigital.ru и при необходимости дополнительный текущий адрес sborka.awwk.chatgpt.site. После публикации проверить прием просмотров и целей в кабинете Метрики. В отчетах проверять данные после обработки сервисом. Блокировщики могут препятствовать сбору, поэтому отсутствие события само по себе не означает отсутствие заявки

Документация: https://yandex.ru/support/metrica/ru/code/counter-initialize и https://yandex.ru/support/metrica/ru/objects/reachgoal

## Перенос на Timeweb

6 октября владелец разрешил запуск на Timeweb, перенос кода в main и отказался от отдельной БД. Next.js работает в Москве, OpenAI и Telegram вызываются через общий ретранслятор в Нидерландах. Подготовлен корневой Dockerfile, Node standalone и общие серверные обработчики

Состояние доставки и лимиты в Node хранятся в памяти одного процесса. Тексты заявок и контакты в отдельную БД не записываются. После перезапуска защита от повторов сбрасывается, опубликованные сообщения остаются в Telegram. Перенос таблиц D1 и последовательности номеров на Timeweb не выполняется

Сначала проверяем приложения на технических адресах, затем владелец добавляет sborkadigital.ru. Полный путь формы в браузере проверяется после привязки домена с согласованным PUBLIC_ORIGIN. Секреты передаются только через защищенное окружение, не через Git или клиентскую сборку

Конкретные переменные, порядок создания, ограничения и откат: [инструкция Timeweb](timeweb-deployment.md)

Метрика подключена в коде, цели и прием событий проверяются в кабинете после запуска. Формальная политика и реквизиты оператора остаются отложенным этапом по решению владельца
