# Аналитика и перенос на российский хостинг

## Метрика

Подготовлена интеграция, включается серверной переменной YANDEX_METRIKA_ID с числовым ID счетчика. Ключи Яндекса не требуются. Пока ID не задан, скрипт Метрики не загружается и события не отправляются. Локальные версии счетчик не запускают

В интерфейсе Метрики нужно создать цели типа «Целевое событие» с точными идентификаторами:

| ID | Событие |
| --- | --- |
| intake_open | Переход к форме заявки |
| intake_start | Отправка первого описания задачи |
| brief_ready | Получен итоговый бриф |
| contact_review | Открыта карточка проверки контакта |
| lead_sent | Сервер подтвердил доставку заявки |
| demo_order | Оформлен условный заказ в демо |

Демо не отправляет ecommerce-выручку и не засчитывается как заявка. Номер, контакты и переписка не передаются в параметры событий. Вебвизор, карта кликов, автоматический сбор внешних ссылок и Яндекс Тег Менеджер отключены. Просмотры передают только фиксированный путь страницы, без query и hash, referer только с origin. Автоматические цели и сбор содержимого форм в кабинете счетчика не включать

Проверка после получения ID: настроить счетчик для итогового домена, задать переменную, проверить загрузку библиотеки и появление целей в отладке Метрики. В отчетах проверять данные после обработки сервисом. Блокировщики могут препятствовать сбору, поэтому отсутствие события само по себе не означает отсутствие заявки

Документация: https://yandex.ru/support/metrica/ru/code/counter-initialize и https://yandex.ru/support/metrica/ru/objects/reachgoal

## Что переносим

Фронтенд уже статический: dist/client. Он может обслуживаться обычным веб-сервером. Серверные маршруты в server/worker.ts рассчитаны на Cloudflare Workers: ASSETS, D1, доверенный CF-Connecting-IP. Простое копирование фронтенда не переносит рабочую форму

После выбора российского провайдера:

1. Подготовить серверный запуск API и постоянную базу вместо D1, настроить доверенный адрес клиента за прокси
2. Перенести секреты средствами нового хостинга, не через Git и не в публичную сборку
3. Перенести таблицы intake_leads, intake_receipts и их последовательность номеров. На время финальной синхронизации исключить параллельный прием заявок на двух базах
4. Проверить доставку, идемпотентность, лимиты и восстановление после перезапуска. Настроить резервную копию и проверку восстановления
5. Подключить домен и HTTPS на тестовом адресе, затем переключить DNS. Сохранить прежнюю версию для отката

AI-часть требует отдельного решения: Россия отсутствует в официальном списке поддерживаемых стран OpenAI API. Не считать прямой вызов с российского сервера рабочей схемой и не обходить ограничения. Выбрать провайдера модели, доступного для согласованного размещения, и заново проверить качество брифа

Источник: https://developers.openai.com/api/docs/supported-countries

От владельца нужны ID счетчика, домен и выбранный хостинг или доступ к его настройке. Формальная политика и реквизиты оператора остаются отдельным отложенным этапом по решению владельца. Перенос сам по себе не подтверждает соответствие всем требованиям к обработке данных
