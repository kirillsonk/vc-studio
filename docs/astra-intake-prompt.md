# Промпт для Astra: бэкенд AI-заявки

Скопировать целиком в Astra.

```text
Подключи бэкенд для AI-заявки на сайте студии «Сборка». Репозиторий: github.com/kirillsonk/vc-studio, ветка main.

Сначала прочитай: AGENTS.md, BRAND.md, docs/intake-flow.md, docs/intake-api.md, src/site/intake/contract.ts, src/site/intake/client.ts, src/site/intake/mock.ts. Фронтенд уже готов и работает на моке. Интерфейс, тексты и дизайн не меняй. Твоя задача: серверная часть и переменные окружения.

Что сделать:

1. Два серверных эндпоинта строго по контракту из contract.ts и docs/intake-api.md:
   - POST /next: вызывает модель OpenAI и возвращает следующий вопрос или бриф
   - POST /submit: принимает финальную заявку и отправляет ее в Telegram
   Базовый URL эндпоинтов передается сайту через NEXT_PUBLIC_INTAKE_API_URL при сборке (например https://<домен>/api/intake). Сайт собирается как статика (next.config.mjs, output: 'export'). Если хостинг позволяет серверные функции рядом со статикой, размести их там. Если нет, сделай отдельный сервис и настрой CORS только на домен сайта.

2. Модель для /next:
   - Самая легкая актуальная модель OpenAI с поддержкой Structured Outputs (класс mini или nano). Проверь актуальное название модели в документации OpenAI, не бери из памяти
   - Системный промпт и JSON Schema возьми дословно из docs/intake-api.md
   - temperature низкая, max output tokens около 600, таймаут 15 секунд
   - Приведи ответ модели к контракту сайта: поле internal клиенту не отдавай, храни его в серверной сессии по sessionId (или пересчитай при /submit) и добавляй в сообщение в Telegram
   - Сервер сам гарантирует лимиты: не больше 5 вопросов (при answers.length >= 5 или forceSummary всегда summary), options не больше 4
   - Если модель вернула мусор или упала: ответь HTTP 502. Сайт сам продолжит на локальном сценарии

3. Доставка в Telegram для /submit:
   - Бот через Bot API sendMessage в чат владельца. Токен и chat_id только в секретах сервера
   - Сообщение: заголовок брифа, пункты брифа, исходный текст задачи, вопросы и ответы, контакты, internal.notes, clientType, complexity, страница и utm, id заявки
   - Отправляй как обычный текст без parse_mode, чтобы текст клиента не ломал разметку. Длинное сообщение режь на части до 4000 символов
   - Ответ сайту { ok: true, id } только после успешного ответа Telegram. Иначе { ok: false, error }
   - Идемпотентность по sessionId: повторный submit той же сессии не создает дубль, возвращает тот же id

4. Безопасность и лимиты:
   - Ключ OpenAI, токен бота и chat_id только в секретах. Никаких NEXT_PUBLIC_ для них, ничего в репозиторий
   - Валидация всех полей: task до 4000 символов, answer до 600, contact до 200, значения брифа до 800, schemaVersion = 1, consent = true в /submit
   - Контакты никогда не отправляются в OpenAI. В /next их и нет, не добавляй
   - Rate limit по IP: /next не больше 30 запросов в 10 минут, /submit не больше 5 в час
   - Лимит расходов в аккаунте OpenAI попроси выставить владельца

5. Переменные окружения:
   - Сервер: OPENAI_API_KEY, OPENAI_MODEL, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, ALLOWED_ORIGIN
   - Сборка сайта: NEXT_PUBLIC_INTAKE_API_URL, по желанию NEXT_PUBLIC_PRIVACY_URL (ссылка на политику обработки данных)
   - Опиши их в README без значений

6. Проверка:
   - curl на /next: пустые answers, 2 ответа, forceSummary true, 5 ответов, мусорный текст, попытка prompt injection
   - curl на /submit: успешная доставка, повтор того же sessionId, невалидные поля
   - В браузере: пройти диалог целиком на десктопе и на 390 px, убедиться, что вопросы адаптивные и не повторяют сказанное, а заявка пришла в Telegram
   - Перед пушем: npm run check:copy, npm run typecheck, npm run build

Правила текста из AGENTS.md обязательны для всего, что видит клиент и что уходит в Telegram: буква е вместо буквы с двумя точками, без длинных тире, AI вместо ИИ, без точек в конце вариантов ответа и подписей.

После работы пришли: где развернут бэкенд, какие переменные нужно заполнить, результаты проверок и 2-3 примера реальных диалогов с моделью.
```
