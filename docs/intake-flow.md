# Заявка через AI-чат

Секция `#intake` на главной: окно чата с границами и собственным скроллом. Клиент пишет задачу в строку ввода, AI задает 2-5 уточнений с готовыми вариантами, собирает бриф карточкой прямо в переписке, затем в той же строке просит контакт. Отдельных форм нет.

## Как устроено на сайте

- `src/site/sections/Intake.tsx`: интерфейс. Шапка с аватаром-атомом и статусом, лента сообщений, строка ввода с печатающимся плейсхолдером, чипы форматов, варианты ответа, бриф с редактированием. Контакт вводится в ту же строку, тип распознается на лету. Состояние диалога хранится в sessionStorage вкладки
- `src/site/intake/contract.ts`: типы запросов и ответов. Единственный источник правды для бэкенда
- `src/site/intake/client.ts`: вызовы API. Без `NEXT_PUBLIC_INTAKE_API_URL` работает локальный мок
- `src/site/intake/mock.ts`: мок модели. Спрашивает только о том, чего нет в задаче: кто клиент, формат, материалы, срок, бюджет
- `src/site/intake/contacts.ts`: распознает email, Telegram и телефон, в том числе несколько в одной строке («телеграм @name, почта name@mail.ru»)
- Согласие: подпись под строкой на шаге контакта, отправка контакта означает согласие

## Режимы

- **Мок** (сейчас): вопросы и бриф собираются в браузере, отправка никуда не уходит. Последнее сообщение ассистента прямо говорит, что это тестовый режим
- **Боевой**: задать `NEXT_PUBLIC_INTAKE_API_URL` при сборке. Если `/next` не ответил или ответил не по контракту, сайт молча продолжает на моке, заявка не теряется. Если `/submit` не прошел, клиент видит ошибку и может повторить

## Правила

- Явные контакты распознаются в любом сообщении и маскируются перед вызовом модели. Подтвержденные контакты передаются в Telegram через `/submit`
- Ключи OpenAI и Telegram хранятся только на сервере. Не добавлять их в `NEXT_PUBLIC_*` и в репозиторий
- Успешная отправка показывается только после ответа сервера `ok: true`
- Для сбора контактов нужна политика обработки данных: ссылка задается через `NEXT_PUBLIC_PRIVACY_URL`

Контракт API и системный промпт модели: `docs/intake-api.md`


## Этап подключения API

С 24 сентября серверный маршрут `/api/intake/next` собирает бриф с GPT-5.4 mini. Контакты распознаются в свободном тексте, бриф редактируется перед отправкой. Доступность Telegram проверяется через `/config`. Без получателя поле контакта остается, отправка сообщает о недоступности. Владелец создал бота и разрешил подключение доставки; реквизиты оператора еще не предоставлены. Текущий статус: docs/telegram-delivery.md

## Карта вопросов

AI ищет пробелы в шести областях: результат для бизнеса, пользователи и их действия, функции первой версии, готовые материалы, интеграции и ограничения запуска
Неизвестный пункт не означает обязательный вопрос. Приоритет у информации, которая влияет на объем разработки
Ответы на известное и пропущенное не повторяем. Варианты являются примерами: посетитель может выбрать несколько, написать свое или объединить способы
Контакты собираются отдельным финальным шагом. Найденные ранее контакты показываются для проверки
Бессмысленный или посторонний ввод требует уточнения задачи, а не выдуманного брифа. Семантические решения модели требуют регулярных проверок на реальных сценариях

Перед выбором вопроса модель возвращает внутреннюю карту известных фактов и один недостающий фактор. Эти поля не показываются посетителю и не сохраняются; на следующем шаге карта заново строится из полной истории
